### 13. Стартовая тема для WordPress

Темы в WordPress называют _Шаблонами_, но правильно их все-таки назвать _Темами_ от английского _themes_.

Стартовую тему можно найти на:

- <a href="https://github.com/tidythemes/blankslate">GitHub</a>. Здесь находится пример пустой стартовой темы;
- <a href="https://underscores.me/">Underscores</a> - генератор тем для WordPress.

На _Underscores_ я и сгенерировал стартовую тему, которая скачалась zip-архивом и далее я ее распаковал в _wp-content/themes/geniuscourse_. В Админской панели, перейдя в темы эта тема появилась. Активировал тему. Но необходимо смотреть, чтобы у новой стартовой темы не было уведомлений на обновление - это будет означать, что тема с таким именем в бесплатных шаблонах WordPress уже существует. Лучше будет если такая тема не будеть сущевтвовать не только в бесплатных шаблонах WordPress, но и на территории всего Интернета.

Первым делом открыл файл _style.css_. WordPress первым делом смотрит на этот файл. Если этого файла не будет, WordPress выдаст предупреждение, что тема отсутствует или не работает. В этом файле есть метатеги, находящиеся в начальном комментарии. Я их подкорректировал:

- **Theme Name: geniuscourse** - Название темы.

- **License URI: LICENSE** - URL лицензии. Остается так.
- **Text Domain: geniuscourse** - Text Domain. Необходим для распознавания в коде. Складывается из названия темы. Если в названии темы есть заглавные буквы, они переводятся в строчные, если есть пробел, то вместо него ставится дефис.

### 15. Подключение файлов кода PHP

За подключение файлов кода _PHP_ отвечает функция `get_template_part()`. Пропишу эту функцию в файле _header.php_ в самом начале `<body>`. Далее в корень темы добавлю директорию _partials_ (части кода), в ней создам файлы _part.php_, _part-one.php_, _part-two.php_. Файлы с дефисом называются спецификацией. В этих файлах пропишу следующий код:

```
<?php

echo 'X';

```

, где X - номера файлов 0, 1, 2.

В функции `get_template_part()` задаю параметры где нужно искать эти коды:

- `get_template_part('parts/part')` - открывает код из файла _partials/part.php_, сверху страницы выводится _0_;
- `get_template_part('parts/part', 'one')` - открывает код из файла _partials/part-one.php_, вторым параметром передается спецификация, сверху страницы выводится _1_;
- `get_template_part('parts/part', 'two')` - открывает код из файла _partials/part-two.php_, вторым параметром передается спецификация, сверху страницы выводится _2_.

Третим параметром передается архив с дополнительными параметрами. Мне сейчас дополнительные параметры не нужны, и я его не передаю.

В этом курсе я не буду использовать директорию _template-parts_, в ней лежат файлы контента с похожими названиями описаными чуть выше. Я ее удалю вместе с файлами.

**Итог**: я научился в WordPress выводить части кода из ранее подготовленных файлов.

### 17. Хуки для Шапки и Подвала

Хук для шапки - `wp_head()`, хук для подвала - `wp_footer()`. Для того, чтобы код выводился в шапке или в подвале необходимо функцию вывести через эти хуки.

```
function geinuscourse_meta_tag()
{
	echo '<meta name="author" content="Angol">';
}
add_action('wp_head', 'geinuscourse_meta_tag'); // Мета-тег выводится в <head>
```

```
function geinuscourse_meta_tag()
{
	echo 'Привет Гениальный курс!<br>';
}
add_action('wp_body_open', 'geinuscourse_meta_tag'); // текст выводится в теле вначале <body>
```

В шапке (_header.php_):

- `wp_head()` обязательно должен присутсвовать внутри тегов `<head></head>`. `wp_body_open` обязательно должен присутствовать вначале тела, т.е. после тега `<body>`.
- `body_class()` обязательно должен присутствовать как параметр тега `<body>`: `<body <?php body_class() ?>>`. Здесь будут содержаться классы необходимые тегу `<body>`. Классы необходимо задавать как параметр хука, т.е. если нужен дополнительный класс, то он задается в параметре, а к нему уже будут выводится те классы, которые заложены в функции.
- Также необходимо, для автоматической генерации языка сайта присутствие `language_attributes()` в теге `<html>` в виде параметра: `<html <?php language_attributes() ?>>`

В подвале (_footer.php_):

- `wp_footer()` обязательно присутствует.

```
function geinuscourse_meta_tag()
{
	echo 'Мои контакты<br>';
}
add_action('wp_footer', 'geinuscourse_meta_tag'); // текст выводится в конце контента перез закрывающимся тегом </body>
```

Хуки принимают третий параметр - это приоритет. Например подгрузка скриптов имеет приоритет `20` и если я поставлю в подвале приоритет `10` то внешне ничего не изменится, но в коде скрипры будут выводиться после текста. При приоритете более `20` текст выведится после скриптов.

### 19. Реализация формы поиска

В _functions.php_ пенеименована функция `geniuscourse_registration_menus()` в `geniuscourse_theme_init()`. В нее добавлена реализация функции `add_theme_support()` для поддержки HTML5 в формах, комментариях и пр.

Создан файл _searchform.php_ в каталоге темы с кодом:

```
<form method="get" action="<?= home_url('/') ?>">
	<input type="search" name="s" value="<?php the_search_query() ?>">
	<input type="submit">
</form>
```

- в _action_ функция `home_url('/')` выводит на главную страницу;
- в теге `<input>`:
  - параметр `name="s"`, именно к `s` прикрепляется get-запрос;
  - параметр в _value_ задается значение функции `the_search_query()`, эта функция выводит последний запрос и он сразу же помещается в поле ввода.

Форма ищет запрос во всех разделах сайта. Чтобы поиск происходил в определенных разделах, например посты, статьи или комментарии, необходимо дописать скрытое поле:

```
<input type="hidden" value="post" name="post_type">
```

По этому коду поиск будет производиться только в постах.

Кастомизировать форму поиска можно и из файла _functions.php_. Можно за ненадобностью удалить файл _searchform.php_ и в _functions.php_ добавить следующую функцию:

```
function geniuscourse_custom_search()
{

	$form = '<form method="get" action="<?= home_url("/") ?>">
	<input type="search" name="s" value="<?php the_search_query() ?>">
	<input type="submit">
</form>';

	return $form;
}
add_filter('get_search_form', 'geniuscourse_custom_search');

```

здесь важно то, чтобы у поля ввода поиска _name_ имел значение _s_. Но с этим моментом у меня будет хуже. ### 20. Безопасный вывод данных (Escaping)

В этом уроке я познакомлюсь с таким понятием как escaping. В WodrPress, в общем как и вообще в Web'е, всю информацию, которая выводится на экран, необходимо очищать от различного кода. Это же касается и информации, которая отправляется в БД.

Работаю в файле _header.php_.

`esc_url()` необходимо применять во всех ссылках, даже тех, которые выводятся функциями, например `home_url()`.
`wp_kses()` имеет 2 парамтеро: строка с тегами и массив атрибутов для этого тега. задает то, что нужно интерпретировать. Например:

```
$name = '<a href="#">Andrey Golovushkin <strong>Angol</strong></a>';

// интерпритирую sthong:

echo wp_kses($name, [
	'strong' => [] // пустой массив потому что нет атрибутов
]);
// Andrey Golovushkin **Angol**

// интерпритирую ссылку:
echo wp_kses($name, [
	'a' => [
		'href' => [], // атрибут href
		'title' => [], // атрибут title, если нужен
	]
]);
// Andrey Golovushkin Angol // текст ввиде ссылки

// интерпритирую ссылку и стронг (все другие теги урезаю):
echo wp_kses($name, [
	'a' => [
		'href' => [], // атрибут href
		'title' => [], // атрибут title, если нужен
	],
	'sthong' => [],
]);
// Andrey Golovushkin **Angol** // текст ввиде ссылки
```

Самые популярные ескейпы:

- `esc_attr()` - используется для ескейпа атрибутов
- `esc_html()` - для ескейпа html-тегов
- `esc_url()` - для ссылок

### 23. Вывод постов в цикле

Настраиваю админку для этого урока: Админка->Настройка чтения->Главная - Ваши последние посты. Проверяю сайт, обновляя Главную. Вижу последние посты. Значит работает файл _index.php_. Пишу свой код:

```
<div>
	<?php if (have_posts()) : /* Посты есть */ ?>
		<?php while (have_posts()): /* Перебор постов */?>
			<?php the_post() ?>
			<?php get_template_part('partials/content') /* Подключаю шаблон контента */ ?>
			<br>
		<?php endwhile ?>
	<?php else : /* Постов нет */ ?>
		<?php get_template_part('partials/content', 'none') /* Подключаю шаблон отсутствия контента */ ?>
	<?php endif ?>
</div>
```

```
<article <?php post_class() /* Подключение классов */ ?> id="post-<?php the_ID() /* ID поста */ ?>" data-post-id="<?php the_ID() /* ID поста */ ?>">
	<h1><?php the_title() /* Вывод заголовка поста */ ?></h1>
	<div>
		<div>
			<?php the_content() /* Вывод контента */ ?>
		</div>
		<a href="<?php the_permalink() /* Ссылка на пост */ ?>"><?= esc_html__('Read more', 'geniuscourse') /* Читать далее */ ?></a>
	</div>
</article>
```

Если постов нет, то в _index.php_ во втором условии (`esle`) прописывается шаблон выводящий сообщение об отсутствии постов:

Заметка:

- у функций, таких как `the_title()`, `the_content()` есть гетеры-аналоги `get_the_title()`, `get_the_content()`. Гетеры отличаются от этих функций тем, что они не выводят на экран, а возвращают значения. И чтобы с ними вывести на экран необходимо перед ними написать `echo` или в HTML-коде написать такую конструкцию: `<?= get_the_title() ?>`

### 24. Регистрация Post Type. #1

Сейчас обучаюсь Custom Post Type.

В Админской панели есть отделные разделы "Посты" и "Статьи", но в БД они хранятся в одной таблице, отличаются только флагом _Post Type_. Можно сделать свой Пост Тайп и в Админской панели появится новый раздел.

К примеру, нужен раздел "Машины". Регистрируется новый Пост Тайп "Car" и появляется соответствующий раздел. Главное, чтобы название не повторяло ряд уже зарегистрированных Пост Тайпов.

Для регистрации Пост Тайпа нужно перейти в файл _functions.php_, создать новый хук:

```
function geniuscourse_register_post_type()
{
	register_post_type('car', $args);
}
add_action('init', 'geniuscourse_register_post_type');
```

Функция `register_post_type()` регистрирует Пост Тайп. Содержит 2 параметра:

1. название Пост Тайпа;
2. массив аргументов.

Массив аргументов описан в комментариях в коде _functions.php_. А также все описание можно найти в документации по ссылке ниже.

Но регистрировать Пост Тайп внутри темы не рекомендуется. При смене темы пользователь потеряет Пост Тайп. Поэтому нужно его выносить в отдельный плагин. Сейчас Пост Тайп регистрируется внутри темы для общего развития. Если делать сайт под ключ для клиента, фриланса, для себя, то это вполне допустимо. Но для разработки темы это запрещено, только в отдельном плагине.

### 33. Персональная пагинация

В этом уроке я буду рассматривать функцию `paginate_links()`, но работать с ней я буду на другой странице.

Сейчас я нахожусь на странице _cars_. Пагинация настроена навывод одного поста на страницу. Но, допустим, мне нужна другая сортировка, где-то в Админке, возможно добавлю такое поле. И на странице с машинами должно быть по два поста, а не по одному. Для этого в файле _archive-car.php_ нужно создать свой _Query_ запрос и получить новый объект с нужными для меня данными.

Вообще можно это сделать не только в архивных страницах, но и в статических, таких как _template-homepage.php_. Автор курса предполагает, что и этот вариант будем рассматривать.

Итак, файл _archive-car.php_. Вначале верстки создаю новый объект `$cars = new WP_Query(['post_type' => 'car', 'posts_per_page' => 2])`, после этого вывожу функции `have_posts()` и `the_posts()` уже от нового объекта `$cars->have_posts()` и `$cars->the_posts()`. Перехожу на страницу, тестирую Пагинацию: ссылки рабочие, адрес соответствует Пагинации, но выводится один и тот же контент, одни и те же две машины. Автор успокаивает, говорит, что это нормально, дело не в Пагинации.

Для исправления этой проблемы необходимо задать третий аргумент в массиве параметров: `['paged' => $paged]`. В переменную `$paged` до этого необходимо поместить переменную запроса страницы `$paget = get_query_var('paget')`. Но и здесь происходит не все так как надо. Машин у меня три. На первой странице выводятся две машины, на второй одна, а Пагинация имеет третью страницу при переходе на которую вижу сообщение, что постов нет. Все дело в том, что в Админке задан вывод одного поста на страницу, значит три машины - три страниыц. Отсюда и берется количество страниц в Пагинации.

Из этой ситуации есть два выхода.

1. Передаю параметры в `paginate_links()` непосредственно в функцию. Заменяю вывод функции кодом взятым из документации WordPress по `paginate_links()`, меняю параметры (см. файл _archive-car.php_). Перехожу на фронт сайта, обновляю страницу и вижу всего две ссылки в Пагинации. Тестирую Пагинацию - все работает. Но такую конструкцию не удобно каждый раз писать.
2. В файле _functitons.php_ создаю фукнцию `geniuscorus_paginate($query)` (см. код в файле) в параметре, которого передается объект _Qurey_. После чего, в нужном месте вывожу эту функцию и передаю в нее объект. Если в аргументах количество страниц передать 3 и более, то Пагинация выводится не будет потому что у меня всего три машины.

Для статических страниц, таких как _template-homepage.php_ переменная запроса, содержащая текущую страницу, называется не _paged_, а _page_. Добавляю в параметр `'paged'` соответствующее значение, после цикла подключаю Пагинацию. В файле _functitons.php_ делаю проверку на тип страницы (статическая или архивная) и передаю соответсвующее значение.

Успешно тестирую сингл страницу и также успешно тестирую архивную старницу.

### 34. Дочерняя тема на WordPress

При работе с WordPress необходимо сохранять его функциональность и "Дочерние темы" - одна из функциональностей.

Зачем нужны дочерние темы? На прошлых уроках я вносил какие-то изменения в код темы: изменял шаблон, функции, добавлял какие-то хуки... Но так с рабочей темой делать неправильно, потому что темы постоянно обновляются, под новые версии WordPress/PHP, добавляются новые функциональности. И при обновлении темы все мои доработки будут теряться. Для этого и нужны дочерние темы. Именно в Дочерней теме, а не в Родительской (основной), будут происходить необходимые изменения, а родительская тема будет постоянно обновляться.

Создание Дочерней темы происходит следующим образом.

1. В корне с шаблонами тем создается директория с названием состоящим из двух частей разделенных дефисом: первая часть - название темы, вторая - _child_. Для моей учебной темы это будет _geniuscourse-child_.
2. В этой директории нужно создать файл _style.css_ и _functions.php_.
   - Файл _style.css_ содержит обязательные параметры: - имя темы; - описание; - автор; - шаблон, это название Родительской темы, у меня это _genuiscourse_; - версия.
     ```
     /*!
     Theme Name: Geniuscourse Child Theme
     Description: Моя первая дочерняя тема на WordPress
     Author: Angol ang0l@inbox.ru
     Template: genuiscourse
     Version: 1.0.0
     */
     ```

Разработка сайта для себя или для клиента не требует изменений в Дочерней теме, за обновление отвечает разработчик темы, т.е. я. Достаточно создать пустую болванку Дочерней темы. Но если сайт делается для фриланса и применяется чужая тема, то нужно все изменения делать в Дочерней теме.

- если сайт пишется с чужой темой - все изменения делаются в Дочерней теме;

- структура директории Дочерней темы должна быть асболютно такой же как и в Родительской. Т.е. если нужно сделать изменения в файле директории _geniuscourse/partials_, тои в Дочерней этот файл должен быть в этой же директории.

### 35. Медиа-файлы и персональные размеры для картинок

Сегодня я буду изучать раздел "Медиа". Здесь можно загрузить медиафайлы, в моем случае это будут картинки. Загружаю в разделе "Медиафайлы"->"Добавить медиафайл". Или можно загрузить в отделной странице, зайдя например, в пост нажав кнопку "Загрузить изображение записи".

Скачиваю <a href="https://unsplash.com/photos/a-glowing-red-moon-reflects-in-water-over-alien-landscape-dFQKK08lHfU" target="_blank">картинку</a> и загружаю ее в WordPress. Эта картинка загрузилась в директорию по адресу: _....\genius.loc\wp-content\uploads\2026\06_. Но в этой директории сейчас не одна картинка, несколько. WordPress нарезает оригинал на разные размеры для того, чтобы вставлять эти "тумбочки" в нужныое место.

Но можно ли сделать так, что бы не в фотошопе резать картинки под нужный именно мне размер, а чтобы это делал WordPress. Да, можно и ответ будет дан в этом уроке.

В файле _functions.php_, в хуке _after_setup_theme_ есть уже прописанная мной функция поддержки тумб `add_theme_support('post-thumbnails');`. Сразу после нее, чтобы не забыть включить поддержку, пишу функцию `add_image_size()`, у нее 4 параметра:

1. имя (id);
2. ширина;
3. высота;
4. понятие - резать или не резать (`true`, `false`), если резать, то массивом передаются аргументы как и откуда резать.

В качестве имени нельзя выбирать зарезервированные слова: _thumb_, _thumbnail_, _medium_, _large_, _post-thumbnail_. Но даже для них можно задавать свои собственные размеры.

Параметры функции `add_image_size('car-cover', 240, 188)` я задал такие, размеры чисто от "балды". Скачиваю новую <a href="" target="_blank">картинку</a> и загружаю ее в WordPress. Теперь нарезанных картинок стало больше на одну и одна из них с шириной 240px, но высота была усечена по пропорции. Если добавить четвертый параметр `true`, то тогда WordPress нарежет ее строго по размеру.

Все тумбы с заданными мною размерами задаются только для новых загружаемых файлов. Все старые, загруженные до объявления функции `add_image_size()` не перерезаются. Для обработки старых картинок нужно установить плагин _Regenerate Tumbnails_. Автор рекомендует его ставить для нарезки картинок. С помощью функции `add_image_size()` можно задать столько размеров, сколько мне необходимо. Чем больше картинок, тем хуже для сайта.

Чтобы изменить размеры по умолчанию, необходимо в _functions.php_ прописать следующий код, например для картинки _thumbnail_:

```
update_option('thumbnail_size_w', 170);
update_option('thumbnail_size_h', 170);
update_option('thumbnail_corp', true);
```

После этого перезапустиь _Regenerate Tumbnails_.

По поводу обрезки (четвертый параметр). Его можно задавать массивом, например: `['center', 'center']` или `['left', 'top']`, и насколько я понимаю, автор умолчал это, можно задавать координаты.

Задам для машины картинку, например для _BMW_ выставлю обложку. В обложке я не могу задать размер: обложка - это обложка.

В файлах _archive-car.php_ и _template-homepage.php_ допишу, что контент нужно брать не из _partials/content.php_, а из _partials/content-car.php_.

В _partials/content-car.php_ пишу код вывода картинки для машины у которой есть картинка (см. код в файле).

### 36. Произвольные поля. Мета-боксы хуком

Для чего нужны дополнительные поля. Я до сих по реализовывал свой функционал посредством Таксономи, регистрировал Таксономи для бренда и года изготовления. Таксономи можно делить на категории. Но у машин есть цена. А у цены нет категорий. Если цену вносить в категории, то получится на сто машин - сто категорий. Это не правильно. Или, коробка передач может быть тольк двух видов: автомат и механика, для них тоже нет необходимости создавать категорию.

Для таких целей можно добавлять текстовые поля. Отдельно текстовое поле, отдельно селект. И уже в этих полях можно задавать или выбирать конкретные данные. Эти поля и называются мета-боксами.

Сейчас сделаю два поля, текстовое для цены и селект для коробки передач.

Есть способ подключить отдельный плагин, есть способ написать код самому. При разработке темы на продажу предпочтительней пользоваться плагином, а при разработке готового сайта для клиента (фриланс) лучше написать самому, чтобы пользователь нечаянно не удалил плагин.

Код мета-бокса буду писать в _inc/metaboxes.php_ и подключу его в _functions.php_.

Написал функцию `geniuscourse_add_metabox()` и колбек функцию `geniuscourse_cars_metabox_html($post)` (см. код в файле).

Весь код, прописанный в _inc/metaboxes.php_ годен для парочки мета-боксов, если мета-боксов много, то есть способы проще, с которыми не нужно изобритать велосипед. С ними я познакомлюсь позже.
