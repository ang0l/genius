### 13. Стартовая тема для WordPress

Темы в WordPress называют _Шаблонами_, но правильно их все-таки назвать _Темами_ от английского _themes_.

Стартовую тему можно найти на:

- <a href="https://github.com/tidythemes/blankslate">GitHub</a>. Здесь находится пример пустой стартовой темы;
- <a href="https://underscores.me/">Underscores</a> - генератор тем для WordPress.

На _Underscores_ я и сгенерировал стартовую тему, которая скачалась zip-архивом и далее я ее распаковал в _wp-content/themes/geniuscourse_. В Админской панели, перейдя в темы эта тема появилась. Активировал тему. Но необходимо смотреть, чтобы у новой стартовой темы не было уведомлений на обновление - это будет означать, что тема с таким именем в бесплатных шаблонах WordPress уже существует. Лучше будет если такая тема не будеть сущевтвовать не только в бесплатных шаблонах WordPress, но и на территории всего Интернета.

Первым делом открыл файл _style.css_. WordPress первым делом смотрит на этот файл. Если этого файла не будет, WordPress выдаст предупреждение, что тема отсутствует или не работает. В этом файле есть метатеги, находящиеся в начальном комментарии. Я их подкорректировал:

Author URI: https: //github.com/ang0l
Description: Моя первая тема на WordPress
Version: 1.0.0

- **Theme Name: geniuscourse** - Название темы.
- **Theme URI: #** - установлена заглушка. Если это коммерческий продукт - нужна ссылка, если это для клиента или для эсперемента можно поставить заглушку или вовсе удалить эту строку.
- **Author: Angol** - Ник или имя автора.

- **Tested up to: 5.4** - на какой версии WordPress тестировалась тема.
- **Requires PHP: 5.6** - на какой версии _PHP_ работает и тестировалась тема.
- **License: GNU General Public License v2 or later** - лицензия. Остается так.
- **License URI: LICENSE** - URL лицензии. Остается так.
- **Text Domain: geniuscourse** - Text Domain. Необходим для распознавания в коде. Складывается из названия темы. Если в названии темы есть заглавные буквы, они переводятся в строчные, если есть пробел, то вместо него ставится дефис.
- **Tags: custom-background, custom-logo, custom-menu, featured-images, threaded-comments, translation-ready** - теги по которым будут находить тему. Строку можно удалить если она не является коммерческим продуктом или продуктом для бесплатных шаблонов WordPress.

### 15. Подключение файлов кода PHP

За подключение файлов кода _PHP_ отвечает функция `get_template_part()`. Пропишу эту функцию в файле _header.php_ в самом начале `<body>`. Далее в корень темы добавлю директорию _partials_ (части кода), в ней создам файлы _part.php_, _part-one.php_, _part-two.php_. Файлы с дефисом называются спецификацией. В этих файлах пропишу следующий код:

```
<?php

echo 'X';

```

, где X - номера файлов 0, 1, 2.

В функции `get_template_part()` задаю параметры где нужно искать эти коды:

- `get_template_part('parts/part')` - открывает код из файла _partials/part.php_, сверху страницы выводится _0_;
- `get_template_part('parts/part', 'one')` - открывает код из файла _partials/part-one.php_, вторым параметром передается спецификация, сверху страницы выводится _1_;
- `get_template_part('parts/part', 'two')` - открывает код из файла _partials/part-two.php_, вторым параметром передается спецификация, сверху страницы выводится _2_.

Третим параметром передается архив с дополнительными параметрами. Мне сейчас дополнительные параметры не нужны, и я его не передаю.

В этом курсе я не буду использовать директорию _template-parts_, в ней лежат файлы контента с похожими названиями описаными чуть выше. Я ее удалю вместе с файлами.

**Итог**: я научился в WordPress выводить части кода из ранее подготовленных файлов.

### 17. Хуки для Шапки и Подвала

Хук для шапки - `wp_head()`, хук для подвала - `wp_footer()`. Для того, чтобы код выводился в шапке или в подвале необходимо функцию вывести через эти хуки.

```
function geinuscourse_meta_tag()
{
	echo '<meta name="author" content="Angol">';
}
add_action('wp_head', 'geinuscourse_meta_tag'); // Мета-тег выводится в <head>
```

```
function geinuscourse_meta_tag()
{
	echo 'Привет Гениальный курс!<br>';
}
add_action('wp_body_open', 'geinuscourse_meta_tag'); // текст выводится в теле вначале <body>
```

В шапке (_header.php_):

- `wp_head()` обязательно должен присутсвовать внутри тегов `<head></head>`. `wp_body_open` обязательно должен присутствовать вначале тела, т.е. после тега `<body>`.
- `body_class()` обязательно должен присутствовать как параметр тега `<body>`: `<body <?php body_class() ?>>`. Здесь будут содержаться классы необходимые тегу `<body>`. Классы необходимо задавать как параметр хука, т.е. если нужен дополнительный класс, то он задается в параметре, а к нему уже будут выводится те классы, которые заложены в функции.
- Также необходимо, для автоматической генерации языка сайта присутствие `language_attributes()` в теге `<html>` в виде параметра: `<html <?php language_attributes() ?>>`

В подвале (_footer.php_):

- `wp_footer()` обязательно присутствует.

```
function geinuscourse_meta_tag()
{
	echo 'Мои контакты<br>';
}
add_action('wp_footer', 'geinuscourse_meta_tag'); // текст выводится в конце контента перез закрывающимся тегом </body>
```

Хуки принимают третий параметр - это приоритет. Например подгрузка скриптов имеет приоритет `20` и если я поставлю в подвале приоритет `10` то внешне ничего не изменится, но в коде скрипры будут выводиться после текста. При приоритете более `20` текст выведится после скриптов.

### 19. Реализация формы поиска

В _functions.php_ пенеименована функция `geniuscourse_registration_menus()` в `geniuscourse_theme_init()`. В нее добавлена реализация функции `add_theme_support()` для поддержки HTML5 в формах, комментариях и пр.

Создан файл _searchform.php_ в каталоге темы с кодом:

```
<form method="get" action="<?= home_url('/') ?>">
    <input type="search" name="s" value="<?php the_search_query() ?>">
    <input type="submit">
</form>
```

- в _action_ функция `home_url('/')` выводит на главную страницу;
- в теге `<input>`:
  - параметр `name="s"`, именно к `s` прикрепляется get-запрос;
  - параметр в _value_ задается значение функции `the_search_query()`, эта функция выводит последний запрос и он сразу же помещается в поле ввода.

Форма ищет запрос во всех разделах сайта. Чтобы поиск происходил в определенных разделах, например посты, статьи или комментарии, необходимо дописать скрытое поле:

```
<input type="hidden" value="post" name="post_type">
```

По этому коду поиск будет производиться только в постах.

Кастомизировать форму поиска можно и из файла _functions.php_. Можно за ненадобностью удалить файл _searchform.php_ и в _functions.php_ добавить следующую функцию:

```
function geniuscourse_custom_search()
{

	$form = '<form method="get" action="<?= home_url("/") ?>">
    <input type="search" name="s" value="<?php the_search_query() ?>">
    <input type="submit">
</form>';

	return $form;
}
add_filter('get_search_form', 'geniuscourse_custom_search');

```

здесь важно то, чтобы у поля ввода поиска _name_ имел значение _s_. Но с этим моментом у меня будет хуже. Дело в том, что уроки старые (2022), а я их учу в 2026, версия WordPress по урокам 5.Х, а у меня 7.0. Возможно, что и у Underscores произошли какие-то изменения, т.к. еще и PHP более новый. ### 20. Безопасный вывод данных (Escaping)

В этом уроке я познакомлюсь с таким понятием как escaping. В WodrPress, в общем как и вообще в Web'е, всю информацию, которая выводится на экран, необходимо очищать от различного кода. Это же касается и информации, которая отправляется в БД.

Работаю в файле _header.php_.

`esc_url()` необходимо применять во всех ссылках, даже тех, которые выводятся функциями, например `home_url()`.
`wp_kses()` имеет 2 парамтеро: строка с тегами и массив атрибутов для этого тега. задает то, что нужно интерпретировать. Например:

```
$name = '<a href="#">Andrey Golovushkin <strong>Angol</strong></a>';

// интерпритирую sthong:

echo wp_kses($name, [
	'strong' => [] // пустой массив потому что нет атрибутов
]);
// Andrey Golovushkin **Angol**

// интерпритирую ссылку:
echo wp_kses($name, [
	'a' => [
		'href' => [], // атрибут href
		'title' => [], // атрибут title, если нужен
	]
]);
// Andrey Golovushkin Angol // текст ввиде ссылки

// интерпритирую ссылку и стронг (все другие теги урезаю):
echo wp_kses($name, [
	'a' => [
		'href' => [], // атрибут href
		'title' => [], // атрибут title, если нужен
	],
	'sthong' => [],
]);
// Andrey Golovushkin **Angol** // текст ввиде ссылки
```

Самые популярные ескейпы:

- `esc_attr()` - используется для ескейпа атрибутов
- `esc_html()` - для ескейпа html-тегов
- `esc_url()` - для ссылок
- `wp_kses()` - имеет 2 парамтеро: тег и массив атрибутов для этого тега. пропускает только тот html, который я разрешаю
- `wp_kses_post()` - содержит все разрешенные для поста теги. похож на wp_kses(), но с 1 параметром
- `wp_kses_data()` - содержит все разрешенные для комментариев теги. похож на wp_kses(), но с 1 параметром
- `esc_js()` - для вставки js-кода, например в кнопку обработчик событий
- `esc_textarea()` - предназначен для текстового поля textarea

### 21. Подготовка файлов темы к переводу

Интернационализация касается не контента сайа, контент пишен пользователь, а касается она больше интерфейса, файлов, там, где есть какие-нибудь названия, имена, кнопок, строк и прочего.

Для этого есть функции:

```
	$hello = __('Hello', 'geniuscourse'); // возвращает результат перевода
	$hello = _e('Hello', 'geniuscourse'); // выводит на экран результат перевода
```

Для подготовки темы к интернационализации мало просто переводить, необходимо еще ескейпить выеденный результат. Но ескейпить можно не помещая реультат в функции ескейпа, а для этого есть свои функции:

```
	$hello = esc_html__('Hello', 'geniuscourse'); // возвращает результат перевода
	$hello = esc_html_e('Hello', 'geniuscourse'); // выводит на экран результат перевода
```

Далее нужно сказать WordPress'у где хранится директория с языковыми файлами. Для этого используется хук `after_setup_theme` и в него нужно дописать вызов функции `load_theme_textdomain()` с двумя параметрами:

1. textdomain. У меня - это `'geniuscourse'`;
2. путь до языового файла, я изменил название директории _languages_ на _lang_ для экперимента и у меня теперь - это `/lang`.

Получилось так: `load_theme_textdomain('geniuscourse', get_template_directory() . '/lang');`

Удаляю вызов функции `load_theme_textdomain()` в коде болванки ниже.

### 22. Шаблоны для страниц (Custom Page Templates)

Из этого урока я узнаю, что такое page template. По русски - это шаблон для конкретной страницы.

В Админке - Настройки - Чтение: Настройки чтения, "На главной странице отображать": по умолчанию установлен "Ваши последние записи". Это значит, что за главную страницу отвечает файл _index.php_. На главно сейчас не контента, потому что удалена директория по умолчанию _template_parts_. Чтобы ее немного заполнить выведу заголовок: `the_title()` и удалю из кода вывод директории по умолчанию. Также закомментировал `get_sidebar()`, чтобы было меньше контента на странице, чтобы лишний контент не мешал просмортру того, что происходит. Далее создал в Админке еще один пост для вывода на главной странице списка постов. Обновил Главную, все работает, выводится Header, Footer, и список постов.

Если нужна конкретная страница на Главной, то в Админке в настройках чтения, "На главной странице отображать" выбираю "Статическая страница" и в списке выбираю ту страниц, которая мне нужна. При перезагрузке во фронте подгружается уже другая страница, за которую уже отвечает файл _page.php_. Но в этом файле напсан шаблон для всех страниц. Для этого в WordPress есть опция Custom Template. В корне темы добавляю файл _template-home.php_. Внутри этого файла в первую очередь пишется комментарий:

```
<?php
/**
 * Template name: Домашняя страница
 */
```

Далее иду в Админку, редактирую выбраную главной страницу, справа выбираю шаблон, в выпадающем списке будет мой шаблон (Домашняя страница), сохраняю. Теперь за эту страницу будет отвечать файл _template-home.php_, а за остальные страницы _page.php_.

Есть второй способ с которым я познакомлюсь далее по курсу. Пока я его не знаю, кроме названия: Мета-блоки.

Третий способ: жестко привязывать страницу к файлу.
В Админке добавляю страницу, например "About" и перехожу на нее во фронт. Убеждаюсь, что за нее отвечает _page.php_, добавив в коде этого файла вывод какой-нибудь строки.
